# Change: HTTP 413 and conditional-status claim corrections

**Date**: 2026-09-20
**Related spec/tasks**: [M1 T009–T011](../../specs/003-m1-task-backbone/tasks.md), [M2 T040–T043](../../specs/001-m2-quality-gate/tasks.md)
**Status**: Implemented and deterministically validated; live qualification remains open.

## Request and scope

Fix both daemon oversized-request handling and the M2 413 answer overgeneralization. The user explicitly requested a commit including the existing source reorganization and documentation changes.

## Changes and decisions

- Preserve the 65,536-byte request cap, but use a non-destroying iterator so an overflow can return JSON 413 / REQUEST_TOO_LARGE before connection closure. Retain 400 for within-cap invalid JSON/schema input and preserve auth/origin/method precedence.
- Add a narrow observed-source guard requiring a cited, verbatim full numeric status ternary for claims mentioning its branch statuses. This rejects the recorded “413 for validation errors” claim instead of inferring a predicate from VALIDATION_ERROR.
- Reuse bounded grounding repair with targeted guidance and advance the prompt contract from v31 to v32. No result schema, budget, snapshot, scope or capability change.
- Follow installed Spec Kit workflow guidance, extend both existing packages and run the prerequisite checker successfully for each. No scaffold or branch was created.
